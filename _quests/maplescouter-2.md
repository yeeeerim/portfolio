## 1. 프로젝트 개요

메이플 환산주스탯 웹 서비스 프론트엔드 리뉴얼

기존 서비스는 CSR 기반 구조와 누적된 UI/UX 문제로 인해 초기 로딩 속도 저하, SEO 한계, 유지보수 어려움 등의 문제가 존재했습니다.
백엔드 로직은 유지하면서, 프론트엔드를 전면 재설계 및 재구축하여 성능, 사용자 경험, 확장성 개선을 목표로 리뉴얼을 진행했습니다.

또한, 프론트 개선 과정에서 드러난 구조적 한계를 기반으로 일부 백엔드 로직 개선을 제안 및 반영하여 전체 서비스 품질을 향상시켰습니다.

## 2. 담당 역할

- 프론트엔드 단독 리뉴얼 수행 (100%)
  - 개선 기획 논의부터 참여하면서 혼자 약 50-60개 페이지를 리뉴얼하여 3개월만에 성공적으로 오픈
  - 레거시 코드 구조 개선 및 컴포넌트 단위 재설계
- 아키텍처 재설계
  - CSR 중심 구조를 SSR 기반 구조로 전환
  - 페이지 단위 렌더링 전략 재정립
- 백엔드 협업 및 개선 제안
  - 프론트 성능 및 UX 개선 과정에서 발생한 병목 분석
  - API 응답 구조 및 데이터 가공 로직 개선 제안 및 반영

## 3. 주요 개선 사항

#### 1. 렌더링 구조 개선 (CSR → SSR)

- Next.js 기반 SSR 도입으로 초기 렌더링 성능 개선
- 주요 페이지를 서버에서 선 렌더링하여 TTFB 및 FCP 개선
- SEO 대응 가능 구조로 전환

#### 2. 성능 최적화

- 불필요한 API 호출 제거 및 요청 병합
- 데이터 캐싱 전략 도입 (React Query 등)
- 컴포넌트 단위 렌더링 최적화 (memoization, lazy loading)
- 번들 사이즈 최적화 및 코드 스플리팅 적용

#### 3. 다국어 지원 및 라우팅 구조 개선

- i18n 구조 전면 재설계
- locale 기반 라우팅 도입 (/ko, /en 등)
- 언어별 콘텐츠 분리 및 확장 가능한 구조 설계

#### 4. UI/UX 전면 재설계

- 사용자 흐름(User Flow) 기반 인터페이스 재구성
- 정보 구조(IA) 개선 및 불필요한 인터랙션 제거
- shadcn/ui 도입을 통한 디자인 시스템 구축

#### 5. 테마 시스템 구축 (다크모드)

- 다크/라이트 모드 전환 기능 구현
- 사용자 환경(OS 설정) 기반 자동 테마 적용
- 디자인 토큰 기반 테마 구조 설계

#### 6. 상태 관리 구조 개선

- Recoil → Zustand 전면 교체
- 전역 상태 최소화 및 도메인 단위 상태 분리
- 불필요한 리렌더링 감소

#### 7. 코드 구조 및 유지보수성 개선

- 컴포넌트 구조 재정의 (Presentational / Container 분리)
- 공통 로직 Hook 분리 및 재사용성 강화
- 타입 안정성 강화 (TypeScript)

## 4. 기술 스택

- Frontend
  - Next.js (App Router)
  - React
  - TypeScript
- State Management
  - Zustand
  - React Query
- UI
  - shadcn/ui
  - Tailwind CSS
- 기타
  - i18n (다국어 처리)

## 5. 성과 및 결과

- 초기 로딩 속도 및 렌더링 성능 개선
- 사용자 흐름 단순화로 UX 개선
- SEO 대응 가능 구조 확보
- 유지보수 가능한 구조로 리팩토링 완료
- 확장 가능한 다국어 및 테마 시스템 구축

## 6. 회고

이번 리뉴얼은 단순히 화면을 새로 만드는 작업이라기보다, 서비스를 다시 설계하는 경험에 가까웠습니다.

기존 구조를 그대로 유지한 채 부분적으로 개선하기보다는,
왜 느린지, 왜 불편한지에 대한 원인을 하나씩 파악하면서 렌더링 방식, 상태 관리, UI 구조까지 전반적으로 다시 고민하게 되었습니다.
특히 CSR 중심 구조에서 SSR로 전환하는 과정이나, 상태 관리 라이브러리를 교체하는 결정은 단순 기술 적용이 아니라 "이 서비스에 어떤 방식이 더 적합한가"를 계속 고민해야 하는 과정이었습니다.

또 하나 인상 깊었던 부분은 사용자 피드백을 직접 반영하는 경험이었습니다.
기존 서비스에서 불편하다고 느껴졌던 UI나 흐름을 개선하고, 실제 사용자 반응을 보면서 다시 수정하는 과정을 반복했습니다.
그 과정에서 단순히 예쁘게 만드는 것보다 사용자가 자연스럽게 사용할 수 있는 구조를 만드는 것이 더 중요하다는 걸 체감했습니다.

또한 프론트엔드 작업을 진행하면서 드러난 API 구조나 데이터 흐름의 비효율적인 부분들을 발견했고, 이를 기반으로 백엔드 로직 개선을 제안하고 반영까지 이어졌던 점도 의미 있었습니다.
프론트엔드 개발자지만, 단순히 화면에만 집중하는 것이 아니라 서비스 전체 관점에서 문제를 바라보고 개선할 수 있었다는 점에서 성장했다고 느꼈습니다.

전체적으로 이번 프로젝트를 통해 기술 선택의 이유, 구조 설계의 중요성, 그리고 사용자 경험 개선까지 하나의 흐름으로 연결해서 고민해볼 수 있었고
무엇보다도 내가 만든 변화가 실제 사용자 경험 개선으로 이어지고, 그에 대한 긍정적인 반응을 확인했을 때 가장 큰 보람을 느꼈습니다.
